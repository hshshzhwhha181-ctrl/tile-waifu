# 0.10 · Путь на 1000 партий (генератор уровней)

Детерминированный генератор 1000 уровней Пути (10 арок × 100), проверка проходимости и бот-оценка сложности.
Основа: CEO_PLAN №1–4 и §3 («пила», «Пики» и «Легендарные», рычаг «глубина лотка», бот подбирает сид в полосу),
IDEAS 5.2 (новая механика каждые 15–30 уровней).

## Файлы

| Файл | Что внутри |
|---|---|
| `level_gen.gd` (`V10LevelGen`) | кривая, арки, расписание механик, `level(i)`, `build(i)`, облегчённая раздача |
| `level_sim.gd` (`V10LevelSim`) | безголовый движок правил лотка + спецфишек v06: проверка сертификата, DFS-решатель, боты |
| `level_board.gd` (`V10LevelBoard`) | доска для игры: `V6SpecialBoard`, который берёт раскладку из payload, а не из случайной раздачи |
| `levels_selftest.gd/.tscn`, `levels_runner.gd` | самотест и запекание (отдельная сцена, `main.gd` не трогаем) |
| `game/data/v10/levels/levels_bake.json` | таблица «соли» сида на каждый уровень (выбрана ботом) + метрики |

Запуск:
```
flock /tmp/tw-godot.lock godot --headless --path game res://scripts/v10/levels/levels_selftest.tscn -- --levels_selftest=1
#   --levels_n=200            только первые N уровней
#   --levels_json=/tmp/m.json метрики по каждому уровню
flock /tmp/tw-godot.lock godot --headless --path game res://scripts/v10/levels/levels_selftest.tscn -- --levels_bake=1
```
Самотест ≈ 75 с (из них 50 с — боты), запекание ≈ 3 мин. Итоговая строка: `LEVELS SELFTEST OK …` / `LEVELS SELFTEST FAIL …`, код выхода 0/1.

## Кривая

- Арка = мир из 100 уровней, глава = 10 уровней. В каждой главе «пила»:
  `1 лёгкий · 2 обычный · 3 обычный · 4 сложный · 5 лёгкий (передышка) · 6 обычный · 7 сложный · 8 ПИК очень сложный · 9 обычный (передышка) · 10 БОСС`.
- Босс главы: главы 1–4 — «Сложный», 5–9 — «Очень сложный» (в первой арке главы 1–2 мягче). Уровень 100 каждой арки —
  «Легендарный», с 3-й арки ещё и уровень 50. Итого: 100 боссов, 18 Легендарных, 139 «Очень сложных» (из них 97 Пиков),
  235 «Сложных», 404 «Обычных», 198 «Лёгких», 6 обучающих.
- Первая арка входит мягко: 1–6 обучение (1–3 на плоском столе), до главы 3 нет пиков, первый «Очень сложный» — 1-38.
- Целевая доля побед «обычного» бота по уровням сложности (`BANDS`): обучение 0.90–1.00, лёгкий 0.85–1.00,
  обычный 0.65–0.95, сложный 0.35–0.65, очень сложный 0.12–0.35, легендарный 0.03–0.15.
  Внутри полосы цель сдвигается вниз от арки к арке (`target_rate`), поэтому 10-я арка тяжелее 1-й при том же составе.
  Бот — заместитель живого игрока; настоящие полосы CEO_PLAN (35–50 / 15–30 / 5–15 %) калибруем телеметрией.

## Как делается доска

1. Параметры уровня (форма из пула арки, ярусы, плотность, верхний узор, число разных лиц, механики) — из таблицы `TP`
   по уровню сложности, с ростом по прогрессу 0…1000. Боссы — тематические формы (корона, фонарь, врата…).
   Маленькие формы дорастают до минимума фишек (`_fit_tiles`).
2. Раскладка — ровно `TrayBoard.gen_layout(cfg)` с тем же сидом, плюс та же обрезка нечётной фишки и сортировка,
   что в `TrayBoard.setup`. Индексы фишек в payload совпадают с `board.tiles`.
3. Порядок снятия: каждый шаг — случайная свободная фишка (с долей `dig` — самая «свежая», копаем вглубь).
4. Пары по порядку с ограниченным лотком: фишка либо «держится» (уходит в лоток), либо закрывает пару с держимой.
   Держим не больше `D` (1 → 3). **Строгая пара**: держимая фишка снята раньше, чем её близнец стал свободным, —
   такие две никогда не лежат свободными одновременно, игрок вынужден держать фишки в лотке («глубина лотка»).
   Доля строгих пар растёт по уровням сложности (`strict` 0 → 0.9).
5. Лица: у пары лицо, которого нет в лотке в момент её открытия; на строгих уровнях две пары одного лица ещё и
   не пересекаются по времени видимости (не подсказывают друг друга).
6. Осколок портрета, золото, перевёртыши, тайные фишки — по правилам `TrayBoard._assign`. Спецфишки v06
   (ключ/замок, цепь, джокер, хлопушка, шкатулка) ставятся на пары сертификата так, чтобы он оставался верным:
   замки — после завершения пары-ключа, цепь — с числом не больше уже собранных пар, джокеры — на подряд идущую
   пару при пустом лотке.
7. Порядок снятия = **сертификат**. Он кладётся в payload и проигрывается в самотесте через движок правил.

## Формат уровня

`V10LevelGen.level(i)` — дешёвый словарь для карты (≈0.7 мс):

```
v10_id, v10_version, v10_salt, assist          индекс 0..999, версия генератора, соль из bake, облегчённая раздача
code "3-47", world 2, num 47, chapter 4, pos 6 (0..9 в главе)
name, loc (=world), stage, bg, fx, art ("w3"), hero, shard, hero_v10, shard_v10
tier "hard", tier_name "Сложный", hard 1 (индекс в G.HARD_NAMES), boss, peak, legend
boss_hero, boss_hero_v10, boss_title           героиня-босс (готовая) и задуманная из ростера 20
intro "lock", intro_line                       вводная механика уровня
shape, cols, rows, layers, fill, faces, upper, seed, tiles      — как у TrayBoard cfg
mech "gold,ice" (совместимо со старым), mechs [...], gold, ice, hidden
v10_plan {gift, lock, lock_n, chain, joker, bomb, event, streak, pool}   — для V6Specials
D, open, old, strict, dig                       параметры генерации
reward {gems}
```

`V10LevelGen.build(i)` ≈ 1.5 мс — то же плюс:

```
v10: { n, pos [x,y,z...], face[], step[], ice[], secret[], gold[], shard[], spec [[a, b, kind, arg]...], cert[] }
cert                                             порядок снятия, проверенный движком правил
```
`kind`: 1 ключ, 2 замок (arg = группа), 3 цепь (arg = N), 4 джокер, 5 хлопушка, 6 шкатулка.

`build(i, -1, null, true)` — **облегчённая раздача** после двух провалов (CEO_PLAN №4): тот же уровень и механики,
параметры доски на две ступени спокойнее, другой сид. Проверяется самотестом; на «Сложных» и выше доля побед бота
0.39 → 0.85.

## Проверки самотеста

- скорость `build()` для всех 1000 < 5 с (сейчас ≈1.5 с; `level()` ≈0.7 с);
- детерминизм: повторная сборка всех 1000 даёт те же доски (хэш payload + сертификата);
- топология симулятора = правила `TrayBoard` (сравнение с перебором);
- **проходимость 100 %**: сертификат каждого уровня проигрывается движком правил без переполнения лотка;
  автоигрок доски (`V10LevelBoard.solver_move`) проходит все 1000; независимый DFS-решатель без сертификата
  (бюджет 600 узлов) тоже решает все 1000, его порядок проигрывается;
- настоящая доска `V10LevelBoard` (каждый 7-й уровень): payload применён, спецфишки на месте, автоигрок чистит стол
  по правилам `V6SpecialBoard` (тот же цикл, что в `spec_selftest`);
- облегчённые раздачи проверены и легче оригинала на «Сложных» и выше;
- боты на каждом уровне: случайный (16 партий), новичок (8), обычный (40), опытный (8). По арке и по уровню сложности:
  фишки, ходы, ветвление (свободных фишек в момент «держать»), удержаний за партию, вероятность тупика у случайной
  игры, доля побед;
- кривая: средние доли побед строго убывают от обучения к Легенде; ≥85 % уровней каждой ступени в полосе (±0.05 —
  шум 40 партий); в 100 % глав Пик/Босс тяжелее передышек; каждая арка не легче предыдущей, 10-я заметно тяжелее 1-й;
  «Очень сложные» в среднем ≤0.40, Легенды ≤0.25;
- расписание: босс каждые 10, финал арки — Легенда, механика впервые появляется на своей вводной, между новыми ≥15
  уровней, вводная не тяжелее «Обычного», все героини уровней есть в сборке.

## Подключение (что нужно сделать в основном дереве — сам не трогал)

1. **Список уровней.** `G._build_levels()` (g.gd): для Пути 0.10 вместо `LOCS × V6Worlds.stages` —
   `for i in V10LevelGen.TOTAL: LEVELS.append(V10LevelGen.level(i))` (≈0.7 с на все; можно лениво по арке).
   Перед стартом партии: `cfg = V10LevelGen.build(i)` (assist: `build(i, -1, null, true)`).
2. **Доска.** `screens/play.gd::_make_board()`: `board = V10LevelBoard.new() if cfg.has("v10_id") else V6SpecialBoard.new()`.
   Без payload `V10LevelBoard` ведёт себя как `V6SpecialBoard`.
3. **План спецфишек.** `V6Specials.plan_for()` в начале: `if cfg.has("v10_plan") and mode == "": return (cfg.v10_plan as Dictionary).duplicate()`.
   Иначе `plan_for` разберёт код «7-38» по старой таблице (ветка `_`) — события/серия будут не те (сами фишки всё
   равно из payload).
4. **Карта.** `V6Worlds.PER_WORLD = 8` → для 0.10 страница арки на 100 точек: главы по 10, узел-босс на `boss`,
   корона на `legend`, огонёк на `peak`, значок механики на `intro`. Плашка сложности до входа: `tier_name`
   (CEO_PLAN §3 «Сложность видна до входа»). Цвета/фоны арок 7–10: `bg`/`fx` пока берут фоны 0.6, ключ `art` = `w7…w10`
   для новых картинок. `G.LOCS[w]` есть только для 0–5 — места, где код индексирует `G.LOCS[lv.loc]`, нужно
   защитить или брать данные из уровня.
5. **Сохранение.** `S.unlocked` сейчас индексирует 48 уровней. Нужна миграция 48 → 1000 (вопрос ниже).
6. **Подстройка после 2 провалов** (CEO_PLAN №4): после второго провала героиня предлагает `build(i, -1, null, true)`;
   звёзды сохраняются, в рейтинге не участвует.
7. **Застревание на замках.** `V6SpecialBoard.unstick()` вызывается только после пары. Если последняя свободная
   фишка ушла в лоток, а остальные свободные — под замком/цепью, игрок застревает без хода. Генератор так не
   проводит сертификат, но игрок может туда прийти. Рекомендация: вызывать `unstick()` и после попадания фишки в лоток.
8. **Доставка по сети** (CEO_PLAN №5): `levels_bake.json` — то, что подменяем с сервера (версия, соль на уровень).
   Замена «5 % худших уровней» = новая соль для них, без нового APK.
9. **Слоты.** Проверка и боты считают лоток из 4 мест (худший случай). Пассивки/дзен с 5–6 местами только облегчают.
10. Хлопушка в симуляторе не взрывается (только помогает) — все выводы консервативны.
11. Экспорт: `include_filter` пуст; `.json` Godot 4 считает ресурсом и кладёт в пакет, но проверить на
    `--export-pack`, что `res://data/v10/levels/levels_bake.json` читается (без него все соли = 0 и кривая хуже:
    сырой генератор попадает в полосы на ~30–60 % вместо 92–100 %). Если нет — добавить `data/v10/*` в `include_filter`.

## Открытые вопросы

- Миграция прогресса: старые 48 уровней → какие из 1000? (предложение: N-й пройденный старый = открыт уровень
  `round(N × 100 / 48)` первой арки, звёзды переносим на ближайшие).
- В 1.0 по плану 300–400 уровней: открывать арки 1–4 сразу, остальные — волнами через доставку по сети?
- Героини арок 7–10 и гостьи-боссы из ростера 20 пока подменяются основательницами (`READY_HEROES`), задуманные — в `*_v10`.
- Полосы — по боту. Нужен замер живых игроков (первые 100 уровней, боссы, Легенды владелец проходит руками).
- Награды за Легенды/Пики («награда за престиж», CEO_PLAN №3) — пока только кристаллы в `reward`.
