# Слепой тест JP-голосов (ворота R-06, GDD §8.4): протокол

Статус: образцы сгенерированы 2026-11-28 (P46), **оценок пока нет** — прослушивание делает человек. Результат ворот (≥70% «не отличают») **не известен**.

## Что проверяем

Можно ли озвучивать героинь ИИ-синтезом на японском так, чтобы носитель языка не отличал его от студийной записи. Порог по GDD §8.4: **≥70% ответов «не отличаю»**. Если порог не достигнут, нужна живая актриса минимум для Маджонг-тян (MT), Юэ и Златы (R-06).

## Состав: 3 модели x 3 голоса x 10 реплик = 90 образцов

| Что | Значения |
|---|---|
| Модели | `seed_audio` (Seed Audio 1.0, 0,20 кр), `elevenlabs_v4` (Eleven v4, 0,23 кр), `text2speech_v2` с движком `minimax` (0,15 кр) |
| Голоса | Luna (читает реплики MT; из `tools/audio/voice_cast.json`), Naomi (реплики Юэ; оттуда же), Helena (реплики Златы; кастинг HANDOFF §3.2) |
| Реплики | 10 категорий Beta-24 из P44 (`game/core/voice/voice_registry.json`): `login_morning`, `intro_summon`, `idle_warm`, `touch_head`, `touch_spam`, `gift_liked`, `level_max_vow`, `fail`, `ult_cast`, `ron`. Каждый голос читает 10 строк **своей** героини |
| Стоимость | смета 17,4 кр (30 x 0,58); по балансу списано 16,8 кр (18695,18 → 18678,38), расхождение 0,6 кр не объяснено; лимит ночи 30 кр |

Тексты строк — черновики модели, **проверка носителем (`[НП]`) не пройдена**. Это важно: если слушатель замечает неестественную фразу, это ошибка текста, а не голоса. Просите слушателей оценивать звучание, а не содержание; странные фразы отмечать в поле заметок, не занижая оценку (в странице заметок нет; передайте устно организатору).

Ограничения, о которых нужно помнить при чтении итогов:

- Сравнение «со студийной записью» делается по памяти слушателя: студийного эталона в тесте нет. Для слушателя-носителя это нормально, для остальных нет (поэтому носитель обязателен).
- Три голоса это пресеты платформы, не финальные голоса героинь: порог проверяет модель в целом, а не окончательное кастинг-решение.
- Каждый голос читает свои реплики, поэтому различия между голосами и между репликами частично смешаны. Решение по голосу читайте с оглядкой на таблицу ячеек модель x голос (она в выводе скрипта).
- `text2speech_v2` на трёх строках выдал аномально длинные файлы (11-18 с на 3-секундный текст: смех и многоточия). Это реальное поведение модели, образцы оставлены как есть.

## Нормализация образцов

По P45: измеритель `tools/audio/lufs_gate.py`, нормализатор `tools/audio/normalize.py` (`--kind voice`, цель −14 LUFS, true peak ≤ −1 dBTP, срез начальной тишины до 10 мс). Файлы, которые нормализатор не смог поднять до цели из-за пика (`limited`), добиваются вторым проходом (усиление и `alimiter`), чтобы все 90 образцов лежали на одном уровне: громкость не должна подсказывать ответ. Итог (`samples_report.csv`, измерено по готовым .ogg): −14,63…−13,95 LUFS, тишина в начале ≤ 17,8 мс. Максимум true peak −0,25 dBTP: после ogg-кодирования несколько файлов чуть превысили −1; для теста это несущественно, для боевых реплик пройдёт обычный гейт.

Имена файлов скрыты: `samples/<хеш10>.ogg` (SHA-1 от соли и тройки модель|голос|строка). Расшифровка в `KEY.csv` — **не открывать до окончания всех прослушиваний**.

## Слушатели

- **Не менее 3 слушателей, из них минимум 1 носитель японского** (отметка в начале страницы). Рекомендуется 5 и больше, включая 2 носителей.
- Слушатель не знает, какая модель какая; при наборе не говорить, что часть записей синтез, пока не закончит (по желанию, но ответ «отличаю» тогда нужно толковать как «вижу, что это не студия»).
- Организатор теста (не слушатель) хранит `KEY.csv`.

## Проведение

1. Открыть `index.html` в Chrome, Firefox или на Android. **Safari и iOS Ogg Vorbis не воспроизводят**, использовать их нельзя.
2. Наушники, тихая комната, громкость системы не менять между образцами. Ввести имя или код (например, L1), отметить «носитель японского», нажать «Начать».
3. Порядок образцов случайный и свой у каждого слушателя (зависит от кода).
4. Для каждого образца: послушать (можно повторно), поставить естественность 1-5 (1 = явно синтетика, 5 = как у студийной сэйю) и ответить «Не отличаю» или «Отличаю» от студийной записи. Без обоих ответов «Дальше» не работает.
5. ~25 минут. Прогресс сохраняется в браузере, страницу можно закрыть и вернуться. Нельзя менять код слушателя на полпути.
6. В конце: «Скачать результаты (CSV)» → файл `results_<код>.csv`. Слушатель отдаёт файл организатору.

## Подсчёт

```
python tools/audio/blind_test.py score design/voice/blind_test/results_L1.csv results_L2.csv ...
python tools/audio/blind_test.py score design/voice/blind_test/        # все results_*.csv из каталога
```

Скрипт читает `KEY.csv` и выдаёт:

- долю «не отличают» и средний балл по модели, по голосу и по ячейке модель x голос;
- число слушателей и носителей; **если слушателей < 3 или нет носителя, решение `INVALID`**;
- отдельно долю среди носителей;
- по каждому голосу: лучшая модель и проходит ли она порог (`ai_ok`);
- решение: модель **проходит**, если её общая доля ≥ 70% **и** доля по каждому из трёх голосов ≥ 70%. Если проходит хотя бы одна модель: «ИИ-голос допустим с этой моделью». Если нет: «живая актриса для MT, Юэ, Златы» (с перечнем голосов, у которых ни одна модель не прошла порог).

Самопроверка скрипта: `python tools/audio/blind_test.py selftest` (маркер `BLIND_TEST SELFTEST OK`).

## После теста

1. Объединить файлы слушателей в `results.csv` (заголовок `listener,native,hash,score,indistinguishable`), сохранить вывод скрипта рядом (`SUMMARY.txt`).
2. Решение записать в `DECISIONS.md` (ворота R-06, Q-14). При провале: заложить бюджет на актрис (владелец), заявление об ИИ-голосе §11.4 уточнить.
3. Пересмотр после прохода: тест повторяется на финальных голосах героинь и на реплике после проверки текстов носителем, до массового заказа Launch-60.
